Unified Social Publishing Execution Contract

Completion boundary for making Awidat's social publishing usable by normal users: connect once, choose destinations, schedule or publish, and let the server handle platform rules and firing.

Review gate before implementation expansion

User Workflow North Star

1. ConnectUser picks a platform and approves in the provider's browser login.
2. ConfirmAwidat shows connected account, capabilities, and any required action.
3. SelectUser chooses one or many destinations from editor, delivery, campaign, render queue, or scheduler.
4. PrepareAwidat generates and validates metadata per platform while keeping one shared pipeline.
5. PublishServer stores artifacts, fires scheduled jobs, retries, polls, and records audit history.

Execution Domains

FirstDomain 1: Publishing substrate correctness
  • Fix artifact storage/read path so server-staged uploads can actually be consumed by workers.
  • Keep server-owned firing, token refresh, retries, and status polling as the only scheduled runtime.
  • Preserve scheduler Slice 1 read-only workspace until write flows are intentionally sequenced.
  • Done when a scheduled YouTube job can use the same storage path created by the desktop/web upload handshake.
SecondDomain 2: Account Center and OAuth
  • Add a unified account center model for YouTube, TikTok, Instagram, Twitter/X, and future providers.
  • Complete server-side OAuth exchange, token storage, refresh, disconnect, reconnect, and required-action states per provider.
  • Done when users can connect accounts without entering secrets or understanding provider setup details.
ThirdDomain 3: Provider upload adapters
  • Keep YouTube live; wire TikTok and Instagram live server clients behind app-review/private-mode flags.
  • Add Twitter/X provider model, OAuth, media/post adapter, limits, and status mapping.
  • Done when each supported provider can move through scheduled, uploading, processing, published, failed, and requires-action states with provider URLs where available.
FourthDomain 4: Metadata profiles and validation
  • Profiles: YouTube long form, YouTube Shorts, TikTok short, Instagram Reel, Twitter/X post, podcast campaign.
  • Validate scopes, account eligibility, media constraints, schedule timing, privacy clamps, rate limits, and app-review restrictions before approval.
  • Done when users see platform-specific constraints before they schedule, not after upload failure.
FifthDomain 5: Product surfaces
  • Connect Account and Publish Drawer appear from account center, editor, delivery, campaign approval, render queue, and scheduler.
  • Scheduler gains source picker, single schedule, bulk cadence preview, account selection, and review drawer writes.
  • Done when the same workflow works from both editor and scheduler without duplicate scheduler systems.
FinalDomain 6: Recovery, audit, and verification
  • Add retry, reconnect, cancel, reschedule, edit metadata, final URL, and immutable event history in one review drawer.
  • Run focused automated tests plus live/sandbox/private checks for each provider path.
  • Done only when current evidence proves every platform and product surface is ready for real users.
