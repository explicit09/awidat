Montage Social Live Verification

This is the release gate for real-user social publishing. Unit tests can prove command shape, but this page defines the live/sandbox/private evidence required before claiming a provider workflow is ready.

Shared Gate

End-to-end workflow evidence

  • OAuth sign-in starts from Montage and returns a connected account via social_accounts.
  • User selects the destination account and edits metadata before publish.
  • Publish path uses social_bind_target, social_validate_target, social_update_target for saved metadata edits on bound jobs, social_schedule_target, and social_upload_artifact.
  • Scheduled app-closed firing is proven from hosted cron/tick logs, not a frontend timer.
  • Status is read with social_publish_job until final provider URL or actionable failure.
  • Evidence includes provider URL, audit history, retry/reconnect behavior, and cleanup.

Provider Matrix

YouTube

private or unlisted first
  • Connect a test channel with upload scope.
  • Upload a short clip as private or unlisted; keep YOUTUBE_FORCE_PRIVATE=true until audit clears.
  • Verify thumbnail, title, description, tags, schedule, provider URL, and cleanup/delete path.

TikTok

sandbox/private first
  • Connect an account approved for video publish capability.
  • Run private or sandbox publish with provider-fetchable artifact URL.
  • Verify public eligibility errors, status polling, provider URL, audit history, and cleanup.

Instagram

sandbox/private first
  • Connect an Instagram professional account through the server OAuth flow.
  • Run private or sandbox publish with caption metadata and provider-fetchable artifact URL.
  • Verify media container processing, provider URL, required action states, audit history, and cleanup.

Twitter/X

private/sandbox account first
  • Connect with PKCE OAuth and media write permissions.
  • Publish a short clip from a test account with non-public blast-radius controls.
  • Verify upload processing, post URL, retry/reconnect behavior, audit history, and cleanup/delete if available.

Evidence Bundle

Required before “ready for users”

  • Update docs/social-server/live-evidence-manifest.json; allProvidersVerified must remain false until every provider check is true.
  • One dated evidence folder per provider with screenshots or JSON logs for account connection, selected account, metadata validation, metadata edit via social_update_target, schedule time, job id, status history, and final provider URL.
  • One hosted-service log slice showing app-closed scheduled app-closed firing for a due job.
  • One negative-path run per provider: missing scope, reconnect required, validation error, or provider requires action.
  • Cleanup proof for every real provider post, or a documented reason cleanup is not possible in that provider mode.
