These define the reversible editing boundary. Replacing them with agent-written media commands would discard inspectability and recovery.

Python indexers and editorial skills

Configured indexers supply distinct media signals; shared sidecars let editing tools reuse those results. Skills encode editing procedures. The survey found connected callers, not evidence for deleting entire signal families or workflows.

FFmpeg, GPU rendering, and browser preview

The backend selector routes GPU transitions separately; browser preview serves interactive playback. These are different execution constraints. Consolidation would need output-parity evidence.

Publishing and scheduling

The desktop connects to real service routes and shared publishing types. Delivery extends beyond local editing, but deleting the service would remove a connected product capability.

Coverage of this sweep

Traced desktop imports and barrel exports, Rust module links and dependency/caller references, Python imports and package entry points, and script/build references. Parsed 116 Python modules and 18 desktop JavaScript scripts. The independent broadcast renderer is deliberately kept: its HTML entry point is used by overlay rendering.

Why some apparently unused code stays

MCP tools, command registrations, package entry points, and the vendored Codex sidecar have indirect consumers. Compatibility readers still handle existing project files. Those paths need evidence of retirement before deletion; “no direct app import” alone is insufficient.

The important assumptions to keep challenging

Migration compatibility: keep compatibility only for identifiable consumers. This was the strongest deletion opportunity.

Multiple implementations: the alternate agent runtime and obsolete UI have been removed. Browser preview and export rendering remain distinct because their execution constraints differ.

Product breadth: publishing, campaigns, and many editorial workflows widen the product. They are connected today. Removing them is a product reduction, not dead-code cleanup.

Review scope: this is a platform architecture and caller survey across Rust, desktop entry points, indexers, skills, rendering, publishing, and build structure. It is not an exhaustive audit of every function or the vendored Codex source.
