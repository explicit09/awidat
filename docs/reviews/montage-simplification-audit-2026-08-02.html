Montage · structural simplification audit

Keep the editor. Remove the parallel products.

Montage has a strong kernel—project protocol, evidence-backed editing, atomic EDL application, and render verification. The weight comes from parallel generations of agent, publishing, render, UI, and “professional” surfaces that were added faster than older paths were retired.

Bottom line

The architecture is recoverable

The foundational flow is coherent: import → index → inspect → propose/apply → render → verify. The safest strategy is to name that as the product kernel, then force every other subsystem to be an adapter, an optional capability, or removed.

no rewritedelete before splittingone canonical path per behavior

Growth outpaced retirement

1,603 commits landed between May 2 and July 25. The repository now contains 261k first-party Rust lines, 63k desktop TS/TSX/CSS lines, and a 1.16M-line vendored Rust runtime. Several comments explicitly describe old paths as superseded while those paths remain compiled and registered.

Do not simplify away hard-won safeguards. Keep atomic timeline writes, validation, picture lock, subprocess timeouts, pending-file cleanup, credential migration readers, render verification, and external-drive mount guards. They protect observed failure modes, not hypothetical architecture.

Recommended cut order

P0

Repair the control plane before touching architecture

make check-app currently fails because its package list still names the deleted montage-tools and montage-sandboxing crates. Remove those entries, delete the no-op legacy_local_publishing feature declaration (or make it real), remove the verified unused direct dependencies, and ignore local .agent-loops/, .codex/, and the root target symlink.

Outcome: the documented development lane works again and repository state reflects the code that actually exists.

High confidence · low risk
P0

Freeze new surfaces and name the v1 kernel

Use one acceptance sentence: “A user can import real media, obtain evidence, make a reviewable edit, render it, and verify the output.” Social scheduling, generated media, secure review/VFX handoffs, and full post-house parity must justify themselves against that milestone before receiving more code.

Outcome: simplification has a product boundary, not just a list of refactors.

Needs product sign-off
P1

Make Codex a sidecar boundary everywhere

The default desktop bridge already uses a thin external JSON-RPC client. The terminal path still falls back to compiling montage-agent-cli, whose normal dependency closure is about 827 packages. Point terminal chat/TUI/resume at the same external sidecar contract, then move the vendored fork into its own workspace/build lane.

Outcome: normal product builds stop treating a 130-crate, 1.16M-line fork as first-party workspace surface.

High confidence · medium migration
P1

Finish or remove the publishing migration

The desktop compiles a 6,919-line local OAuth/upload implementation and a server-backed social implementation at the same time. The manifest calls the local path old, but its feature flag has no cfg use. If publishing stays, migrate the three render-queue upload commands and delete the local path. If it is not v1, extract the entire social product from the editor build.

Outcome: one credential model, one job model, one upload path.

Structure confirmed · scope decision required
P1

Expose a small tool kernel; reveal the rest by skill

Keep a directly visible primitive set (project/readiness, timeline inspection, apply, render/poll/verify, skill load, diff). Use the existing per-skill allowlists to expose task-specific tools. Do not return to “defer everything”: the July A/B proved organic prompts then bypass tools entirely. Remove no-value wrappers such as attempt_completion, which explicitly does not gate or end a turn.

Outcome: less schema/context weight and fewer overlapping ways for the agent to do the same job.

High confidence · requires live A/B
P1

Delete dormant “professional snapshot” code before reorganizing it

In crates/core/src/professional.rs, 13 of 16 public functions have no production caller outside the file. The dead family includes professional snapshot, VFX package, secure review package, assistant workflow, media operations, color handoff, audio post, delivery master, and timeline-scale derivation. Preserve serialized protocol fields until migration policy is explicit, but stop computing structures nothing consumes.

Outcome: remove speculative application logic without destabilizing the core protocol.

Call graph confirmed · compatibility review needed
P2

Collapse exact skill variants

Six skills—chapter intro, quote highlight, retention-list opener, route map, search-bar sequence, and statistic counter—have the exact same tool allowlist and route through the same proposal/revise/verify implementation. Keep their artifact types as data under one visual-support workflow rather than six separately maintained playbooks.

Outcome: fewer discovery entries and less instruction drift without losing capability.

Exact duplication confirmed
P2

Move state out of App.tsx; prune CSS by rendered coverage

Push project hydration, media readiness, agent-session hydration, and workspace routing into the existing domain stores/controllers. Then delete superseded CSS rules against screenshot baselines instead of adding another override layer. Only after behavior is smaller should timeline.rs and edl/apply.rs be split by domain.

Outcome: the root becomes composition in fact, and styling stops depending on cascade archaeology.
