Montage · first-principles architecture pass · local main

One owner for each decision.
Keep the editing workflow inspectable.

Montage needs to understand media, propose changes, let the user inspect them, and produce a usable video. Duplicate representations that can disagree and unsupported quality scores work against that purpose.

Two proposal queues → one

Deleted the parallel pending-proposal store and duplicate event ingestion. Timeline, Brief, and inspector now share the same revision and selection. Stale deltas cannot rewind the queue or recreate completed proposals; arrival time and revision history remain.

Three alternate layouts → none

Deleted unused cockpit implementations from Delivery, Skills, and History, their variant switches, and orphaned supporting components. Removed the hidden Skills setup and History search state used only by those branches.

Invented confidence → actual findings

Deleted the 72%/90% delivery-confidence calculation and meters. These were derived from warning presence, not measured render quality. Duration, selected outputs, preflight findings, and render status remain.

Review the edit, not a guessed location

Split and trim navigation now converts the actual source edit point to current playback time, including speed. Clip ranges still support highlighting; review position is represented separately. The fixture now uses the protocol’s real trim-side value.

Keep the Rust project / EDL / render boundary

The timeline is editable, reversible project state. EDL validation and render execution are distinct responsibilities; replacing them with agent-generated shell commands would discard those guarantees. Browser preview and export also have different execution requirements.

Keep one external agent runtime and indexed media facts

The Codex sidecar already owns agent execution. Rust dispatches indexers; Python packages produce reusable media facts. No evidence in this pass justified porting model-backed indexers to Rust or merging their distinct signals.

Keep publishing separate from editing

Publishing has account, upload, and scheduling responsibilities. It is broader than local editing, but removing connected delivery capabilities would be a product-scope change. This pass removes duplicate presentation, not supported delivery behavior.

What this does and does not settle

This pass examined current desktop state ownership and surfaces, EDL proposal persistence, the MCP editing entry point, index dispatch, rendering boundaries, and delivery structure. It does not establish that every subsystem is minimal. In particular, proposal acceptance still deserves a separate concurrency check against intervening timeline edits; this pass does not claim to change backend persistence.

Large files alone are not a reason to split them. The useful next changes should remove duplicated authority or enforce a concrete contract, not just redistribute line counts.

Evidence

The stale-revision regression failed before consolidation and passes afterward. Focused checks cover completion followed by a late delta, background revisions, selection, Brief decisions, feedback, and split/trim navigation at different speeds.

Desktop typecheck and production frontend build passed. The frontend test sequence passed the non-browser checks. All 5 workspace browser smoke checks and all 7 rendering goldens passed using a temporary browser; Delivery, Skills, and History screenshots were visually inspected. The Skills IPC fixture now returns a real-shaped list instead of the generic null response.

Changes remain local on main. This pass does not claim a packaged release, backend concurrency fix, model-indexer run, or live publish.

Deletion first: one lifecycle implementation, one layout per surface, and no fabricated delivery-quality metric. No new framework or automation.
